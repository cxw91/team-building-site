# 团建管理小网站

一个面向小团队团建的后勤管理站点：把「谁出人、谁带东西、谁买什么、谁花了多少钱」都记在同一个页面上，多人协作时靠轻量版本探针按需同步彼此的操作（不是服务端推送）。**支持同时管理多个团建项目**，每个项目的数据彼此隔离。

**技术栈**：Cloudflare Pages（静态前端） + Pages Functions（接口） + D1（SQLite 数据库）。整套东西都在 Cloudflare 免费额度内，无需自建服务器。

## 功能一览

| 模块 | 说明 |
| --- | --- |
| 口令进入 | 用**已注册的口令**（邀请码）登录，不注册个人账号；每个口令对应一份独立的项目数据，登录后进入**项目中心**，且只看得到本口令名下的项目 |
| 口令管理 | 登录页右侧的**「管理口令」弹窗**：列出口令、管理员密码、备注名与各自名下的项目数，支持新增 / 修改 / 删除；**只认超级密码**（`SUPER_PASSCODE`），未配置时该功能直接停用 |
| 项目中心 | 登录后新建团建项目（名称 + 备注），或从历史项目列表进入已有项目；项目可改名、结束/重启、删除。**新建项目、项目改名、结束项目、删除项目、重启已结束的项目都需要本口令的管理员密码**；点「删除」直接弹出密码框，不再有行内「确认删除 / 取消」这一步。**同一口令下项目名称不可重复**：新建与改名都校验（去首尾空格、忽略英文大小写），重名返回 `409`，不同口令之间互不影响 |
| 家庭与人数 | **不内置任何家庭和人数**：创建项目时手动添加家庭，每行填「家庭 / 小组名称 + **成员人数** + 一条备注（忌口 / 过敏）」，人数可留空按 0 处理、限 0～999 的整数；**不再录入或展示成员姓名**（历史库里已有的姓名数据保留，不参与人数口径）。进入项目后可新增家庭，自家可修改名称、人数与备注，其他家庭仅可查看（**卡片用灰调底 + 虚线描边 + 标题旁「其他家庭 · 只读」角标**，深浅主题各一套配色，与自家卡片一眼可分）。家庭人数是「按人数均分」结算的权重。**同一项目内家庭名不可重复**（去空格 + 忽略大小写），新建项目表单各行、成员页新增家庭与改名都校验，重名返回 `409`；不同项目之间互不影响，历史重名数据保留。项目内顶栏的**「切换家庭」改成就地下拉**：点一下在按钮下方直接列出本项目全部家庭，点选即切换并同步刷新界面，不再跳到单独的选择界面（首次进入项目、还没有归属时仍会显示选择家庭页）|
| 概览看板 | 总花费、**项目预算**、**每家应摊**（按人数口径显示各家应摊区间；括号里只保留人数 / 家数）、家庭数 / 总人数、携带与采购完成进度、最近操作；卡片区下方是**「预算与花费进度」**（显示「总花费 / 预算」并按进度变色，未设置预算时显示「无」），右侧是**「设置预算 / 修改预算」**入口（需要本口令的管理员密码） |
| 项目预算 | 每个项目可设一个预算金额（元）；概览与采购记录都显示「总花费 / 预算」，**只有进度条与百分比按花费进度变色：进度 < 60% 绿色、60%～100% 橙色、超过预算红色**（面板本体用普通面板底色，与「总花费」卡片一致，不跟着档位变色）。填 0（或留空保存）即可取消预算设置、回到「无」。概览里点「设置预算 / 修改预算」只在前端就地展开金额输入框、点「取消」也只在前端收起，**这两步是纯前端切换、即时生效，不会重新拉接口**；点「保存」并输入本口令的管理员密码后才写入数据库（不点保存不会改动数据）。**设置 / 修改 / 取消预算都需要本口令的管理员密码** |
| 携带物品 | 每个家庭自己维护自家的携带物品，**所有家庭都能看到**（只读他人）；**「非自家」卡片用灰调底 + 虚线描边 + 标题旁「其他家庭 · 只读」角标**，深浅主题各一套配色，且不铺流光 / 光斑；自家卡片仍是常驻浅紫实线边，一眼可分（成员页的非自己家庭卡片同款）。每条物品按**「物品名字：xxx　数量：xx」两列左对齐**展示，名称列与数量列起点固定、多行上下对齐；数量留空显示「数量：未填」，不再用名称后面的圆角数字标签。自家物品点「修改」可**就地改数量**（名称不改），回车 = 保存、Esc = 取消，留空即清空数量；别家的物品没有「修改 / 删除」，接口层也会拒绝 `403`。**同一家庭内物品名不可重复**（去空格 + 忽略大小写）：添加时前端即时提示、后端返回 `409`；别家已有同名物品不拦，历史重名数据保留 |
| 采购清单 | 项目内公共的「要买什么」清单，任意家庭可增删（**已经登记过采购记录的项不能删**，删掉对应的采购记录后即可删）；每项可**接任务**（认领后显示由哪个家庭负责），认领家庭可**取消接单**；**已经采购过（清单里为「已购」）的项不再给「取消接单」**——要退回「未接单 + 待购」只能删掉对应的采购记录。**「待购 / 已购」由「采购记录」自动同步，清单里谁都不能手工切换**（登记了采购就变已购，删掉那笔记录就回到待购并清空接单家庭）。同一行的「接任务」「待购/已购」「X 接单」字号尺寸一致，**未接任务为橙色、已接任务为蓝色**，一眼可辨；行内所有操作控件统一为**同尺寸胶囊按钮**（高 26px、水平间距 8px），并在**手机端整组靠右排布、「删除」紧贴在最后一个状态按钮右侧**（删除为红色描边，与普通操作分成两级）。**手机端每行按「名称一行 + 浅色副信息一行 + 控件另起一行」排版**（与采购记录页的两行式一致），不会被挤成竖排 |
| 采购记录 | 记录每一笔「谁买的、买了什么、花了多少」，并汇总每家已垫付金额。**记入当前已选家庭**，无需在页面里再选一次。物品名称**只能从「当前家庭已接任务」的采购项里选，不能手工新增**（还没接单就先回采购清单接任务）；登记后该项在清单里变「已购」。**只能删除自家登记的记录**，别家的记录只显示「他家登记」。**「各家采购金额」面板内显示「总花费 / 预算」进度条**，并按进度变色（< 60% 绿、60%～100% 橙、超过预算红；未设置预算时显示「预算：无」且不着色）|
| 结算 | **两种分摊口径可手动切换**：按家庭数均分（默认）/ 按人数均分。切换写入项目、需要本口令的管理员密码，所有家庭看到同一口径；算出每家应摊与差额，给出**最少笔数**的转账建议。任务奖金池的出资始终按家庭数均分，不随分摊方式改变 |
| 操作日志 | 家庭粒度的操作流水（谁家、何时、做了什么），30 秒一次的轻量版本探针发现变化后才刷新当前页签，切页签、主动操作、切回前台或点顶栏「刷新」都会立即同步，**别人操作后通常 30 秒内可见**；**单条日志可删除，也可以用日志页右上角的「清除全部日志」把当前项目的日志一次清空，两者都需要本口令的管理员密码**（清除只作用于当前项目，且不可恢复） |
| 主题 | **浅色 / 深色两套主题**，**项目中心顶栏与项目内顶栏各有一个太阳／月亮图标按钮**（浅色主题显月亮、深色主题显太阳；登录页与选择家庭页不放入口）；选择记在浏览器本地，下次打开自动恢复，**没手动选过时跟随系统的深浅色偏好**。配色取自随工程提供的两份配色稿件，弹窗、提示条与下拉候选框在深色下同样跟随深色，详见「主题（浅色 / 深色）」一节 |
| 只读查看 | 项目**结束**后进入只读模式：仍可查看全部内容，但任何修改都被禁用与拒绝；用本口令的管理员密码重启项目后才恢复可编辑 |

## 多项目模型

- 一个口令 = 一个团队（租户）。团队下可以有多个**团建项目**（如「2026 春季团建」「2026 秋季团建」）；**不同口令之间的项目数据互相隔离**，登录某口令只能看到、也只能改到它名下的项目。
- **项目名唯一（限同一口令内）**：新建项目与项目改名都按「去掉首尾空格 + 忽略英文大小写」判重，命中返回 `409 该口令下已存在同名项目「X」，请换一个名称`；**不同口令之间互不影响**，两个口令各叫「2026 秋季团建」是允许的。前端在弹管理员密码之前先用当前项目列表预检，后端按 `projects.passcode_id` 做最终裁决（多端 / 并发以库为准）。**不建数据库唯一索引、不改历史数据**：老库里已经存在的重名项目保持原样，只是之后不能再新建或改成重名。
- 每个项目**独立**拥有自己的家庭（含人数与忌口备注）、携带物品、采购清单、采购记录、**项目预算**、**结算分摊方式**与操作日志，项目之间数据互不影响。
- **家庭名唯一（限同一项目内）**：新建项目时一次填写的多行家庭名互不重复，成员页「新增家庭 / 小组」与「修改家庭」改名同样按「去掉首尾空格 + 忽略英文大小写」判重，命中返回 `409 本项目已存在同名家庭「X」，请换一个名称`；新建项目里两行重名返回 `409 家庭名称「X」重复了，请合并或修改其中一行`。**不同项目之间互不影响**；前端在弹管理员密码 / 发请求之前先用缓存家庭列表预检，后端按 `families.project_id` 做最终裁决。**不建唯一索引、不改历史数据**：老库里已有的重名家庭保持原样，只改人数 / 备注也不会被误拦（只有名称真的变化才判重）。
- **项目预算**：每个项目可设一个预算金额（元），概览与采购记录都会显示「总花费 / 预算」并按进度变色；**设置 / 修改 / 取消预算都需要本口令的管理员密码**。预算存在 `projects.budget` 字段（`0` 表示未设置、页面显示「无」）。
- 每次业务请求都会带上当前项目标识（`X-Project-Id`），接口层按项目做隔离，不会串数据。
- 家庭与人数**不预置**：建项目时在表单里逐行填写「家庭名称 + 成员人数 + 备注（忌口 / 过敏）」即可；进入项目后也能新增家庭、修改自家的人数与备注。人数只存一个整数，不按姓名逐条记录。
- **家庭自助边界**：进入项目时要选定一个家庭身份（写请求带 `X-Family-Id`）。**只能修改自己家庭的名称、人数与备注**，其他家庭在成员页仅可查看；接口层同样校验，越过界面直接改他人家庭会被拒绝（`403 只能管理自己家庭的信息，其他家庭只能查看`）。未选定家庭身份时写家庭信息会返回 `403 请先选择你所属的家庭`。
- **分摊口径**：项目级设置，两种口径手动切换，详见下方「分摊口径」一节。新增 / 删除家庭会改变按家庭数均分的结果；修改家庭人数会改变按人数均分的结果。
- **项目状态**：每个项目有「进行中 / 已结束」两种状态。**结束项目与重启已结束的项目都需要本口令的管理员密码**（在项目中心点「结束」或「重启」都会先弹出密码框）。
- **已结束 = 只读**：项目结束后再进入，仍能看到全部历史内容，但所有编辑控件被禁用，接口层也会拒绝写入（返回 `403 项目已结束，只能查看…`）。要用本口令的管理员密码重启为「进行中」才能继续修改。
- **回到项目中心**：项目内右上角三横菜单里的「**项目中心**」（位于「退出」正上方）→ 回到项目列表，行为与原先顶栏那个独立按钮一致；选择家庭页另有「返回项目中心」链接。**项目内顶栏不再单独放「项目中心」按钮**，只保留「刷新 / 主题 / 菜单」三项，菜单顺序为「切换家庭 › → 分隔线 → 项目中心 → 退出」。点菜单项后先收起下拉并复位 `aria-expanded`，再切视图，避免下次进项目时状态残留。

## 家庭人数与分摊口径

### 人数登记

- 每个家庭只登记**一个整数人数**（`families.member_count`，0～999）和**一条备注**（`families.note`，忌口 / 过敏）。新建项目弹窗、成员页的「新增家庭」与「修改」都用同一组字段。
- 不再录入、也不再展示成员姓名。旧版按姓名写入的 `members` 行**保留在库里**、`/api/members` 的 GET 仍可查，但所有写接口一律返回 `403 成员已改为按「家庭人数」登记…`，界面也没有逐成员列表。
- 老库升级时，后端只在 `member_count` 是本次新建出来的情况下，把每个家庭的历史成员行数**回填一次**；之后人数以 `families.member_count` 为准，改动不会影响历史姓名数据。用户主动设成 0 人的家庭不会被反复改回去。
- 项目中心卡片「N 位成员」与概览「总人数」都来自 `SUM(families.member_count)`。

### 两种分摊方式

| 口径 | 总花费分配 | 顶部 KPI | 结算表 |
|---|---|---|---|
| 按家庭数均分（默认 `family`） | 每家 1 份，按「分」精确分配，余数按小数部分补齐 | 每家应摊（N 家均分） | 家庭 / 已垫付 / 应摊 / 差额 |
| 按人数均分（`person`） | 按各家人数加权，人数为 0 的家庭应摊 0 | 每家应摊区间（共 N 人；各家最小～最大，相同时显示单值） | 多一列「人数」 |

- **切换**：结算页顶部的分段按钮，写入 `projects.split_mode`，需要本口令的**管理员密码**（与设置预算 / 奖金同级），并写一条「修改分摊方式」日志。口径是项目级的，所有家庭与设备一致；已结束的只读项目不能切换，但仍可按当前口径查看。
- **不再展示「人均应摊」**：奖金池出资始终按家庭数均分、不随人数加权，人均值只是混合口径的平均数，与结算表里任何一家的应摊都对不上，无法用来核对账目。概览与结算的顶部卡片统一按「每家」口径展示，数值直接取自结算明细，口径以后端 `effective_mode` 为准。
- **卡片文案与顺序**：标签不再重复「按人数加权」「含奖金池」等口径说明，括号里只保留人数 / 家数 / 兜底原因，即「每家应摊区间（共 N 人）」「每家应摊（N 家均分）」「每家应摊（暂无人数 · 暂按 N 家均分）」。概览与结算同步。结算页顶部卡片顺序为「总花费 → 任务奖金池（设置了才显示）→ 每家应摊」；下方表格面板顺序为「任务奖金（设置了才显示）→ 每家结算 → 结算建议」。
- **0 人兜底**：项目选了「按人数」，但所有家庭都是 0 人时，分母为 0，后端临时退回按家庭数均分。顶部卡片显示「每家应摊（暂无人数 · 暂按 N 家均分）」，结算页提示「当前项目还没有登记任何人数，已临时按家庭数均分」，表格仍保留「人数」列；此时切换按钮仍停在「按人数」。
- **任务奖金池不受分摊方式影响**：出资始终按家庭数均分，获得始终按各家已完成的采购任务数分配。因此差额公式不变：`差额 = 已垫付 + 获得奖金 − 应摊`。
- **转账建议**按当前口径的差额重算，仍是贪心最少笔数。
- 分摊方式只改变展示与计算口径，**不会自动改写已经发生过的转账**；切换前已按旧口径结清的账目，请自行对照新口径复核。

## 两套密码：超级密码与「口令的管理员密码」

站内有两个层级的密码，各管一段、互不顶替。

**1）超级密码（`SUPER_PASSCODE`）——只管「口令管理」**

- 用于登录页右侧的**「管理口令」**弹窗：列出口令、新增口令、修改口令、删除口令。
- 打开「管理口令」会先弹「需要管理权限」验证超级密码（列表要等验证通过才加载）；此时**点「取消」或在密码框按 Esc 会直接关闭所有弹窗、回到输入口令的登录界面**。验证成功 / 出错仍留在「管理口令」弹窗；项目内其它高风险操作的「取消」只取消该操作、保留下层表单。
- 口令管理**只认超级密码**；旧的 `ADMIN_PASSCODE` 在这里会被拒绝（`403 超级密码不正确`）。
- 未配置 `SUPER_PASSCODE` 时，口令管理**一律直接拒绝**并提示：`500 服务器未配置超级密码（环境变量 SUPER_PASSCODE），口令管理暂不可用；请先在 Cloudflare 后台或本地 .dev.vars 配置后重试`。

**2）每个口令自己的「管理员密码」——管该口令下所有项目的项目级高风险操作**

- 一个口令 = 一个团队（租户）。**同一口令下的所有项目共用这一个管理员密码**；不同口令各有一条自己的管理员密码，互不影响——这正是为了区分「不同口令下的项目却用同一个管理密码」的问题。
- 管理员密码存在 `passcodes.admin_passcode`，在「管理口令」弹窗里新增 / 修改口令时一并设置（**新增时必填**）。
- 登录某口令后，令牌与该口令绑定；服务端由此判定「当前登录口令」，再取它自己的管理员密码来校验下面的操作，**不会回退全局 `ADMIN_PASSCODE`**。

| 操作 | 位置 | 未通过校验时 |
| --- | --- | --- |
| 新建团建项目 | 项目中心「新建团建项目」→ 填好后点「创建项目」（成功后停留在项目中心，手动点「进入」才打开项目） | `403 该操作需要本口令的管理员密码` / 密码错为 `403 管理员密码不正确`；项目名重名 `409`；表单内家庭名重复 `409` |
| 项目改名 | 项目中心历史项目右侧「改名」→ 保存 | 同上 |
| 删除单条操作日志 | 日志页每条右侧「删除」 | 同上 |
| 清除项目全部日志 | 日志页右上角「清除全部日志」 | 同上 |
| 结束项目 | 项目中心历史项目右侧「结束」 | 同上 |
| 删除整个团建项目 | 项目中心历史项目右侧「删除」（直接弹密码框，无行内二次确认） | 同上 |
| 重启已结束的项目 | 项目中心 / 项目内把状态改回「进行中」 | 同上 |
| 设置 / 修改 / 取消项目预算 | 概览页「预算与花费进度」右侧「设置预算 / 修改预算」 | 同上 |
| 切换结算分摊方式 | 结算页顶部「分摊方式」分段按钮（按家庭数 / 按人数） | 同上 |

使用时前端会弹出一个密码输入框，**弹窗里会写明这次要输的是「超级密码」还是「本口令的管理员密码」**：点「确定」后按钮立即进入加载态（转圈 + 「验证中…」），此时密码框与「取消」一并禁用；密码正确则弹窗关闭并执行操作，密码错误则**停在弹窗内提示并可重试**，无需重新点一遍触发按钮。

**`ADMIN_PASSCODE` 现在的角色**：它**不再**参与项目级操作的校验，只作为「管理员密码」的**初始值 / 兜底回填**——本版升级时，还没有管理员密码的口令会用当前 `ADMIN_PASSCODE` 初始化；之后每个口令都可以在「管理口令」里改成自己的密码。

- 本地：在 `.dev.vars` 里配置，与 `PASSCODE` 并列，例如 `ADMIN_PASSCODE = "admin2026"`、`SUPER_PASSCODE = "super2026"`。
- 线上：在 Pages 项目的 **Settings → Variables and Secrets** 里添加同名变量（详见部署章节）。
- 「清除全部日志」清除的是**当前进入的那个项目**的日志（按 `X-Project-Id` 隔离），不会动到其它项目。
- 服务端通过请求头 `X-Admin-Passcode` 读取本次要校验的密码：口令管理走 `functions/api/[[path]].js` 的 `requireSuper()`（比对 `SUPER_PASSCODE`），项目级操作走 `requireProjectAdmin()`（比对当前登录口令的 `admin_passcode`）。

## 采购清单 ↔ 采购记录 的联动口径

- **认领有颜色**：采购清单同一行里，「接任务」「待购 / 已购」「X 接单」几个控件的字号与尺寸完全一致；其中**未接任务＝橙色「接任务」**、**已接任务＝蓝色「X 接单」**，一眼就能分辨谁接了、谁没接。
- **手机端排版**：窄屏（≤560px）下每一行拆成上下三块——**名称独占一行**；下方是**浅色副信息行**（`数量 · 单位`、备注、「某家 接单」蓝色标记、接单时间）；「接任务 / 取消接任务」「待购 / 已购」「删除」等控件**整体另起一行、并整组靠右对齐到行尾**。宽屏下副信息与控件仍在名称右侧、右侧本就贴边，排版不变。
- **控件外形统一、整组靠右**：采购清单行内所有控件（接任务 / 取消接任务 / 待购 / 已购 / 删除）都是**同高 26px 的胶囊按钮**、圆角一致、组内水平间距 8px；**整组控件右对齐到行尾，「删除」永远是最后一个控件、紧贴在左侧状态按钮右边**，靠红色描边与普通操作分成两级。于是已接单的行是「取消接任务｜待购 / 已购｜删除」，他家的接单行是「待购｜删除」，未接单的行是「接任务｜待购｜删除」，三种形态都贴着行尾排，左侧留白一致。触控目标不小于 26px，满足手指点击。
- **状态来自采购记录，不由清单自己说了算**：采购清单里的「待购 / 已购」不是手工字段，而是按**采购记录**现算——还存在指向该项的采购记录就是「已购」，一笔都没有就是「待购」。因此：**登记一笔采购 → 该项自动变「已购」**；**删掉那笔记录 → 该项回到「待购」，并清空接单家庭、回到「没人接任务」**（接单标记与接单时间一并消失）。同一项有多笔记录时，删掉其中一笔不改变状态，**删掉最后一笔才回落**。接口层直接登记到「还没人接单」的项时，仍会把接单家庭记为登记家庭（界面上走不到这条路径，因为名称只能选本家已接单项）。
- **「已购」不给「取消接任务」**：已经采购过的项（清单里派生成「已购」）不再提供「取消接单」入口；接口层直调 `PUT { "claim": false }` 同样被 `403` 拦住，提示「这一项已经采购过了，不能取消接任务；删掉对应的采购记录会自动回到「未接单 + 待购」」。**让它回到「未接单 + 待购」的唯一路径就是删掉指向它的采购记录**（自家登记的那条），删干净后接单家庭与接单时间一并清空；**待购**（还没登记过采购）的项仍可正常取消接单。
- **采购记录只能删自家的**：每条记录挂在登记它的家庭名下，**只有该家庭能删**；别家的记录在明细里只显示「他家登记」，接口层直调返回 `403 只能删除自家登记的采购记录，其他家庭只能查看`。
- **物品名称只能选、不能新增**：名称控件是**自绘下拉**（不再用原生 `<datalist>`——它的弹层由浏览器绘制、颜色不受 CSS 控制，深色主题下没法保证配色，也不能主动收起）。候选**只列「当前家庭已接任务、且还没登记过采购」的采购项**（他家的、还没接单的、**已经采购过（已购）的**都不出现）；输入框是**只读**的，键入不会写进内容，只能点开候选选一个；右侧箭头（按 `16×16` 居中渲染，按钮内 `padding` 已归零，不会被挤成一条竖线）可随时展开 / 收起，收起后不占位、不遮挡下方内容。**选中某一项之后不会被锁死**：想换一项，重新点右侧箭头、或直接点名称框，都能再次展开完整候选（列表恒列当前全部可选项，不会只剩下已选的那一条）。键盘可用：`↑` `↓` 在候选间移动、`Enter` 选中、`Esc` 收起，焦点移开后自动收起。本家还没有接单项时候选会提示「先去采购清单接任务」；如果绕过界面往输入框里塞非候选名称，提交会被前端拒绝并提示，不会落库。
- **保留他家的接单**：若同名项**已被其他家庭接单**，登记采购只把状态改成「已购」，**不会抢占**原来的接单家庭，避免误改责任归属。
- **删除按口径回退**：删除一条采购记录时，只当该同名清单项**此刻仍是「本笔记录的家庭接单 + 已购」**，才把它退回「未接任务 + 待购」；其它情况（被别的家庭接单、或已经不是已购）保持不变，不会误清别人的接单。
- **已经登记过采购记录的清单项不能删**：清单项一旦有采购记录指向它（派生成「已购」），行内的「删除」会变成**不可点**的状态（中性灰字、无 hover 反馈、`not-allowed` 光标，`title` / `aria-label` 写明原因，页面下方的规则说明里也写了这一条）；接口直调删除同样返回 `403`。把指向它的采购记录删掉后，该项回到「未接单 + 待购」，删除立刻恢复可用；**未登记采购记录的项（不管有没有人接单）照常可删**。
- **删除按钮统一危险色**：携带物品、采购清单、成员等所有行内「删除」都由 `dangerCell()` 生成，用 `--danger` 红字 + hover 淡红底，与同排的品牌紫「修改」分成两级；禁用态（含项目结束只读时被整体禁用的删除）统一压成 `--muted` 中性灰并去掉 hover，不会变成「淡一点的红色」让人误以为还能点。删除确认弹窗里的「确定删除」是另一套实心底样式，不受影响。
- **删除采购记录不需要密码**：它属于普通的更正操作，与「两套密码」一节列出的新建 / 改名 / 删除项目、结束 / 重启项目、设置预算、删除日志等高风险操作（需要本口令的管理员密码）不同。
- **确认框不做「轻关闭」**：`#confirmModal` 故意不挂遮罩点击与全局 Esc 监听，误点弹窗外一片或顺手按 Esc 都不会把危险确认框关掉，**只能显式点「取消」**；删除流程结束由 `hideConfirm(true)` 统一收起。其它弹窗（管理密码 / 口令管理 / 新建项目）的关闭行为不受影响。
- **确认删除后弹窗原地进入加载态**：家庭 / 携带物品 / 采购清单 / 自家登记的采购记录这四类删除共用 `#confirmModal`。点「确定删除」后弹窗**不再立刻消失**，而是原地切成「正在删除××…」转圈（`#confirmModal.is-busy` + `aria-busy="true"`，两个按钮 `disabled`，加载期间「取消」也被挡住）。一直等到 `DELETE` 成功、删家庭时额外拉一次 `/families`、以及 `render()` 整页重新取数重画完成，才关闭弹窗并弹「已删除」——弱网下用户不会盯着旧数据反复点。加载态至少显示 450ms，网络快时不会一闪而过；期间 30 秒版本探针暂停。失败（含取数失败导致界面停在「加载失败 + 重试」）一律关闭弹窗 + toast 报错，不误报「已删除」；`DELETE` 超过 15 秒视为超时，同样关弹窗并提示「删除结果未知，请稍后点「刷新」确认」，不给重试入口。日志 / 项目 / 口令管理等其它删除入口不走这条路径，行为不变。
- 关联命中顺序：优先按登记的 `item_id` 命中清单项，其次按**同名项**（完全同名，同一项目内）命中；清单里没有同名项时不新建，只登记这笔采购。

## 主题（浅色 / 深色）

站内所有用于着色的颜色都收敛成一套语义令牌，两套取值**分别取自 `深色主题.html` 与 `浅色主题.html`**（随工程提供的配色稿件）。令牌定义在 `public/style.css` 顶部的 `:root`（浅色）与 `html[data-theme="dark"]`（深色）。

### 切换入口与记忆

| 位置 | 表现 |
| --- | --- |
| 项目中心顶栏 | 「退出登录」右侧一个图标按钮 |
| 项目内顶栏 | 「刷新」与汉堡菜单之间的一个图标按钮（顶栏共三项：刷新 / 主题 / 菜单） |
| 登录页 | **不显示**主题入口 |
| 选择家庭页 | **不显示**主题入口 |

> 登录页与选择家庭页是两块居中的窄面板，单独挂一个主题图标显得突兀，所以这两处不放入口；要换主题，进到项目中心或项目内顶栏点一下即可。而**记忆与跟随系统照旧生效**——之前手动选过的主题、或者系统的深浅色偏好，登录页依然按它渲染，只是不在这里提供切换按钮。

### 图标（太阳 / 月亮）

两个入口用的是同一对**线条（描边）风格图标**：**浅色主题显示月亮**（点下去切到深色），**深色主题显示太阳**（点下去切回浅色）。

- **形状**：太阳＝描边圆环＋八根放射短线（四正四斜）；月亮＝一条闭合的缺月轮廓，开口朝右上。两个图标同一视觉家族——24×24 画布、描边 1.7、圆头圆角端点、同样的基准尺寸与对齐方式；形状取自随工程提供的图标参考图。
- **只定义一次**：两个图标写在 `public/index.html` 顶部一个隐藏的 `<svg><defs>` 里，两处按钮用 `<use href="#icon-sun">` / `<use href="#icon-moon">` 引用，改一处即可同时生效。
- **显隐靠 CSS、不靠 JS**：`html[data-theme]` 一变就换图标，所以首屏（脚本还没跑完）也不会闪出错误的图标。
- **尺寸与触控**：图标 18×18，按钮约 26×30（含内边距），不小于非文字控件的最小点按目标；顶栏里这个按钮不折行、不挤压「刷新 / 主题 / 菜单」，390px 窄屏下顶栏仍是一行。
- **可访问性**：两个 `<svg>` 都是装饰性的，带 `aria-hidden="true"` 与 `focusable="false"`，不参与朗读；语义由按钮承担——`title` 与 `aria-label` 写的是**点下去会切到哪个主题**（浅色主题下是「切换到深色主题」，深色下是「切换到浅色主题」），鼠标悬停与读屏都能明白。**状态不只靠图形**，图标切换的同时可访问名称也跟着换。
- **颜色**：描边用 `currentColor`，跟随按钮的文字令牌 `--muted`——浅色 `#757575`（对白底 4.61:1）、深色 `#bdbdbd`（对卡片底 7.31:1），都超过非文字控件要求的 3:1；悬停时提亮到 `--text`。
- **图标来源与授权**：按图标系统路由确认，本项目是原生 HTML/CSS/JS 的静态站点（无 React、无打包器），而 ReIcon 路线要求 React 与精确锁定包版本、平台原生图标面向 App、UI 图标又明确不允许交给生图；因此路由结论为 `provider = host-project-inline-svg`（`provider_owner = host-project`）。据此**不引入任何第三方图标包、不走 CDN、无网络依赖**，两个图标就地写在页面里，授权上也没有外部资产需要清权。

- **即时生效**：点击后立刻给 `<html>` 换 `data-theme`，不用刷新；同时切 `color-scheme`（输入框、滚动条等原生控件跟着变）与浏览器地址栏的 `theme-color`。
- **记忆**：选择写入 `localStorage["tb_theme"]`，下次打开自动恢复，且不会被系统偏好覆盖。
- **跟随系统**：从没手动选过时读 `prefers-color-scheme`；一旦手动选过，就以手动选择为准。
- **不闪色**：`public/index.html` 头部有一段极短的引导脚本，在样式表加载前就把 `data-theme` 定好，避免刷新时先闪一下浅色再跳深色。

有两处与稿件不同，都是为了可读性做的最小调整，想改回严格照搬只需各动一行：

1. **深色主题的次要文字用 `#bdbdbd` 而不是 `#757575`**。稿件的 `SecondaryTextColor` 是 `#757575`，它在 `#2d2d30` 卡片底上只有 **2.98:1**，12–13px 的次要文字会偏暗；这里改用同一份稿件里给「说明文字」用的 `#bdbdbd`（卡片上 **7.31:1**、页面底上 9.07:1）。浅色主题仍是 `#757575`（白底 4.61:1）。

### 深色主题里的浮层

**深色主题下所有浮层都跟随深色主题**：弹窗卡片用 `--card`（`#2d2d30`）、输入框用 `--field`（`#1c1c1c`）、文字用 PrimaryText（白色），轻提示条用亮一级的 `#424242`，物品名称的下拉候选框同样全走令牌。深色弹窗另外加一道 1px `--line` 细边、遮罩改成 60% 压暗（`BlurGradientValue 0x99000000`），保证深底再压暗之后浮层边界依然清楚。

> 这里与配色稿件有一处**有意的偏离**：《深色主题.html》第 6 节建议深色主题用 `BackgroundColor #eeeeee` 做对话框，最初也照此做成了「浅色浮层」；但实际使用中反馈弹窗「主题颜色不对」——深色界面里突然弹出一整块亮面过于跳脱，因此改为跟随深色。要回到稿件的浅色浮层，把 `public/style.css` 里 `html[data-theme="dark"] .modal-card` 那条规则换回 `--card: #eeeeee; --field: #ffffff; --text: #212121; --muted: #757575; …` 即可。

### 主题的验收口径

用无头 Chrome 真实渲染逐项断言，两套主题各测一遍（脚本放在工程外的工作目录，不随包分发）：

- 令牌取值与稿件**逐项相等**；正文对比度浅色 13.88 / 16.10、深色 17.04 / 13.73（WCAG AA ≥ 4.5）。
- 390px 与 1000px **无横向溢出**（顶栏加按钮后仍不挤行、按钮不折行），采购清单「控件整组靠右、删除贴右缘、26px 等高、8px 间距」保持不变。
- 待购 / 已购 / 接任务 / 删除**四态颜色在两套主题下互不相同**；深色下分别取自 `--btn-bg` `#686868`、`LightSuccess` `#113a1b`、`LightWarning` `#4c3a0f`、`LightDanger` `#450c0f`。
- 深色下弹窗、提示条、下拉候选框都随深色主题（弹窗 `#2d2d30` 底 + 白字、提示条 `#424242`、候选项高亮用 `--primary-soft`）。
- **逐页对照两套主题的计算样式**：全站没有一个元素的「背景色」或「文字色」在两套主题下取值相同——仅剩配色稿件刻意同值的 `--primary` 蓝与主色上的白字。
- **物品名称控件**：候选只列**本家已接单且还没登记过采购**的项（他家的、还没接单的、已经采购过的一律不出现）；输入框只读——真实键盘输入打不进内容，程序写入非候选名称提交会被前端拒绝、有提示且不落库；聚焦即展开、点箭头可收起（收起后 `hidden`、高度归零）、`↑` `↓` 高亮并可 `Enter` 选中、`Esc` 收起、失焦自动收起；**选过一次之后点箭头或点名称框都能重新展开，列表仍是全部可选项、能改选别的项**；本家没有可登记项时给出明确空提示；两套主题下候选框底色 / 边线 / 文字都取自令牌。**箭头图标按 `16×16` 渲染并在 30×30 按钮里居中**（`<use>` 的 `getBBox()` 为 8×4、按钮 `padding` 为 0），页面上不会出现被压扁的图标。
- **状态派生与删除权限**：接口层手工改状态一律 `403`（无人接单 / 他人接单 / 自己接单三种情况都一样）；登记一笔采购后该项变「已购」，删掉记录后回「待购」且接单家庭被清空；同一项还剩别的记录时删掉其中一笔仍是「已购」、接单家庭保留；清单里状态是只读 `span`（页面上 `toggle-shop` 按钮数为 0），概览的「已购项数」与派生值一致；采购记录只有自家那几笔有删除入口，他家记录显示「他家登记」，乙家直调接口删甲家的记录返回 `403`。**已购项在界面没有「取消接任务」入口**（该行只剩「已购 + 删除」两个控件），接口直调 `PUT { "claim": false }` 返回 `403` 且接单与已购都保持不变；删掉那笔采购记录后该项自动回「待购」并清空接单家庭，界面也变回可再「接任务」。
- 端到端回归：在弹窗里填名称与家庭能真正创建并进入项目、管理权限弹窗输入密码能删掉日志、从候选里选一个登记后清单项变「已购」、再从界面删掉那条记录后清单项回「待购」且接单标记消失、接任务 / 取消接任务、退出后重新登录，全部通过。
- **图标**：主题入口共 2 个（项目中心顶栏、项目内顶栏），都渲染成图标（按钮内没有可见文字）、渲染尺寸 18×18；浅色下只显示月亮、深色下只显示太阳，点击后主题与图标一起互换；`<use>` 指向已定义的 `#icon-sun` / `#icon-moon`；两套主题下图标描边色分别是 `rgb(117, 117, 117)` 与 `rgb(189, 189, 189)`。
- **入口范围**：登录页与选择家庭页里 `#loginView` / `#pickView` 内都没有主题按钮（DOM 与可见元素均为 0），两块面板的最后一项分别是提示行与「返回项目中心」，没有留下空白节点；两处面板仍水平居中、无横向溢出；这两页刷新后依旧按存档与系统偏好渲染主题。
- 放大到 5～6 倍截图逐个核对过图标形态：深色下是「描边圆环＋八根放射短线」的太阳，浅色下是「开口朝右上的闭合缺月」，与参考图同属线条风格。
- **结束项目的密码门禁**：接口直调 `PUT /api/projects/:id { "status": "已结束" }`，不带 `X-Admin-Passcode` 返回 `403 该操作需要本口令的管理员密码`、带错返回 `403 管理员密码不正确`、带对才成功且项目变「已结束」（结束后的只读守卫、以及重启仍需密码这两条既有口径都不回退）；界面上点「结束」先弹密码框（提示本次要输「本口令的管理员密码」），不输密码只提示「请输入密码」、输错停在弹窗内可重试、输对才结束，点「取消」不结束；结束后卡片显示「已结束」、按钮文案变「重启」。
- **已购清单项不可删除**：清单里已购项的「删除」是 `disabled` + `aria-disabled` 状态（颜色取 `--muted`、`cursor: not-allowed`、`opacity: 0.7`，浅色/深色一致），`title` / `aria-label` 写明原因，点击不产生任何请求、也不进入确认态；未登记采购记录的行删除保持红色危险样式，仍能两步删掉；接口直调删除已购项返回 `403` 且清单项仍在；把指向它的采购记录删掉后，该项回落「未接单 + 待购」、删除按钮恢复可用并能真的删掉。
- **切页签与轮询重建的一致性**：连续快切页签（点 A 后立刻点 B，共 24 轮，覆盖 采购清单↔概览 / 采购清单↔日志 / 采购记录↔概览 / 结算↔成员），每轮稳定后「页签高亮」与「内容归属哪个页签」必须一致——守住「重建是异步的（各页先拉接口、之后整体赋值 `#content`）」时，旧页签的在途重建不会把内容盖回旧页签。

## 加载、数据同步与弱网体验

进入项目、切换页签时先给反馈再等网络，避免「侧边栏能点、内容区却一直不动」；数据同步走「动作触发 ＋ 30 秒版本探针（变更时才拉数据）」两条路，没有服务端推送。

- **30 秒版本探针（数据同步主节奏）**：不按固定节奏拉业务数据。每 30 秒只发 **1 个** `/api/logs?since=<游标>&limit=1`（走主键索引、最多返回 1 行）问「数据变没变」；有变化才 `revalidate` 当前页签，全量取数仍做指纹比对、没变化不重画。后端所有写操作都会 `addLog` 且 `logs.id` 是 `AUTOINCREMENT`（单调递增、删日志不复用），日志 id 就是项目级版本号；游标只增不减，日志被清空后新日志照样能检测到，首次探测只建基线、不会把历史日志误判成变更。
- **为什么不每 10 秒全量轮询**：Workers Free 只有 **10 万请求/天**（UTC 重置，超限 Error 1027），Pages Functions 的 `/api/*` 都算。历史实现里概览页一轮 4 个 GET → 一个人 24 小时开着就是 34,560 次，约 3 个人就打满。改成探针后空闲时只有 1 个请求/30 秒（约 2,880 次/天/人），且只有真有变更才产生业务请求；现在业务取数又收敛成 1 个聚合请求（见下），再叠加「无交互暂停」，实际开销通常是每天几百次/人。
- **暂停与生命周期**：页面隐藏、首屏数据还没取到、编辑态（行内编辑 / 输入框聚焦 / 候选框展开）、写请求在途、弹窗打开，或**连续 5 分钟没有交互**时都不发探针（动鼠标 / 敲键盘 / 切回前台重新计时）；后台连定时器都不跑。探针失败静默沿用缓存，只有主动刷新失败才给轻提示。定时器只在 `show("appView")` 启停，返回项目中心 / 选择家庭 / 退出登录自动停掉；换项目 / 退出登录会重置版本游标，避免新项目的日志 id 小于旧游标。
- **手动刷新**：项目内顶栏「刷新」按钮，点击立刻发 **1 个** `/api/page-data?tab=<当前页签>`（绕开 1 秒防抖）重取当前页签，响应里的 `version` 顺带推进版本游标，无需再补一次探针，零空闲开销；也是无交互暂停后要最新数据的直接入口。**点击有动画反馈**：hover 时图标保持静止（没有偏转动画，只有所有顶栏按钮通用的 hover 变色）；点击后图标转圈 + 按钮染品牌色高亮（同时挂 `aria-busy="true"`、`disabled`），结束后放一圈扩散光环；至少转满一圈（600ms）才收起，网络再快也不会闪一下就没了。动画只表示「这次动作进行中 / 结束了」，不暗示成功，失败另有 toast；`prefers-reduced-motion: reduce` 下全部动画关闭，只保留颜色高亮与状态属性。
- **进入项目即出骨架屏**：所有入口（项目中心点「进入」、口令登录后自动回上次项目、刷新页面自动恢复会话）都在 `enterProject()` **发出 `tab=all` 聚合请求之前**就先 `show("appView")` + `renderChrome()` + `showSkeleton()`，立刻切到项目内视图铺占位骨架屏（「正在加载…」＋ KPI 占位卡 ＋ 内容占位行）并挂 `aria-busy="true"`。弱网下最慢的正是这段等待，以前要等聚合取数跑完 `showApp()` 才创建骨架屏，用户全程盯着项目中心。提前时会先清 `state.familyId / state.families`，避免顶栏短暂显示上一个项目的家庭名。`showSkeleton()` 幂等（已在加载态就不重建 DOM），所以 `showApp()` 再调一次不会让微光动画重播；后续取数、降级、重画、失败重试逻辑全部不变。切到还没有缓存的页签时同样铺骨架屏。栅格与真实 `.cards` 对齐，颜色走设计令牌，深浅主题自动适配，尊重 `prefers-reduced-motion`。
- **刷新恢复不再等「正在恢复会话」卡片**：上次停在项目里时，`init()` 检测到本地 token ＋ 上次项目，直接 `show("appView")` + `renderChrome()`（顶栏先用「团建管理」占位，真实项目名等 `loadProjects()` 回来由 `enterProject()` 覆盖）+ `showSkeleton()`，`loadProjects()` 与 `tab=all` 两段等待全程骨架屏。口令失效由 `api()` 的 401 处理踢回登录页，项目已不存在则回到项目中心（骨架屏被换掉）。本地有 token 但**没有**上次项目（上次停在项目中心）时，目的地不是项目内、没有对应骨架屏，仍用「正在恢复会话」卡片兜住这段等待。
- **失败可见可重试**：取数超时 / 出错 / 绘制失败不再静默停在骨架屏，而是显示错误原因与「重试」按钮；点「重试」重新显示骨架屏并重跑当前页签的渲染。项目已结束时「重试」仍可点（`data-readonly-keep`，它不改数据）。
- **读请求 10 秒超时**：`api()` 对 GET 默认 10 秒超时，提示「网络较慢，请求超时，请重试」。**写请求默认不自动超时**——超时后用户重试可能造成重复提交，写操作继续由按钮加载态盯着。**唯一例外**：四类行内删除的 `DELETE` 由 `performDelete()` 显式传 15 秒（`DELETE_TIMEOUT_MS`），因为它的确认弹窗是阻塞式的，请求彻底挂起时会永远转圈；超时错误带 `timedOut` 标记，删除链路把它改写成「网络较慢，删除结果未知，请稍后点「刷新」确认」后关闭弹窗 + toast——**故意不提供「重试删除」**（超时≠失败，可能已删成功，重试会二次提交），用户点「刷新」即可看到真实状态。
- **旧请求作废**：整页渲染带「代次」＋ `AbortController`。切页签时 `abortLoads()` 立刻作废上一页签还在飞的请求，旧响应一律丢弃，不再抢占带宽，也不会把旧页内容盖回来；主动取消（`AbortError`）不算错误态。
- **两套取消信号**：`loadCtrl` 管整页取数，每切一次作废一轮；`bgCtrl` 管后台刷新与版本探针，只在**换项目 / 退出登录**时整体作废，旧项目的数据不会写进新项目缓存。
- **一次取齐 ＋ 缓存优先**：进入项目只发 **1 个** `/api/page-data?tab=all`，一次拿齐项目信息与七个页签的数据（含 `version`），直接把全部页签标记为可绘制，因此不再需要「3 路并发预热其它页签」。概览刷新不再附带全量日志（日志页自己有 `tab=logs`）。切页签时先用缓存立刻画出来，超过 1 秒防抖窗口才后台发 1 个 `/api/page-data?tab=<页签>` 刷新。主动刷新失败保留缓存内容并给一次轻提示（8 秒内不重复弹）；探针失败静默，避免按节奏反复打扰。
- **聚合失败自动降级**：`tab=all` 重试一次仍失败（偶发超时，或前后端版本错配导致端点不存在），就只取项目详情与家庭列表、提示「已切换为逐页加载」，并把后续所有页签取数切回原有单接口，不标记页签缓存，让 `render()` 逐页补齐。降级路径不带 `version`、不推进游标，30 秒探针照常工作。换项目时重新尝试聚合接口。
- **离开即收工**：`logout()` 与 `enterProject()` 先作废所有在途取数，防止旧项目的响应在新项目清空缓存之后写回 `state` 造成串数据。

## 部署到 Cloudflare Pages

前提：一个 Cloudflare 账号；本机装好 Node.js（命令都用 `npx wrangler`，无需全局安装）。

部署分两种情况：**首次部署**（第一次上线，要把 Pages 项目、线上数据库、进入口令都建起来）和**后续更新**（项目已存在，只推代码）。首次部署的顺序比较讲究，见下。

> ⚠️ **`--branch` 必须等于该 Pages 项目的生产分支**，本项目是 `production`（wrangler 首次创建「直接上传」项目时，生产分支的默认值就是 `production`）。它和**本地 git 分支名无关**：本项目是把本地 `public` 目录直接上传，不是 Git 集成部署。不写 `--branch` 时 wrangler 会自动取当前 git 分支（本仓库是 `main`），写错都会变成 **Preview 部署**，而 `PASSCODE` / `ADMIN_PASSCODE` / `SUPER_PASSCODE` 与 D1 绑定通常只配在 Production，结果就是登录 401、接口 500。生产分支可在 Dashboard → **Settings → Builds & deployments → Production branch** 查看，或执行 `npx wrangler pages deployment list --project-name=team-building-site` 看哪条部署被标为 Production；若不是 `production`，把命令里的值替换掉。
>
> `public` 目录参数**照常传**：`wrangler.toml` 的 `pages_build_output_dir = "./public"` 指向同一个目录，wrangler 取 `命令行参数 ?? 配置值`，两者不冲突；省略目录参数时也由配置兜底。

### 一、首次部署

顺序关键点：**Pages 项目必须先存在**，Dashboard 里才能进去配环境变量和 D1 绑定。所以实际顺序是「先建库 → 先部署一次把项目建出来 → 回控制台配口令与绑定 → 再部署一次」。

**步骤 1：创建 D1 数据库**

```bash
npx wrangler login
npx wrangler d1 create team_building
```

命令会输出一段 `[[d1_databases]]` 配置，把其中的 `database_id` 复制到 `wrangler.toml`，替换里面原本的占位值。

**步骤 2：把表结构写入线上 D1**

```bash
npx wrangler d1 execute team_building --remote --file=./schema.sql
# 可选：导入演示数据（1 个示例项目 + 6 个家庭）
npx wrangler d1 execute team_building --remote --file=./seed.sql
```

**步骤 3：先部署一次，把 Pages 项目建出来**

```bash
npx wrangler pages deploy public --project-name=team-building-site --branch=production
```

首次执行会提示创建 Pages 项目（省略 `--project-name` 也可以，按提示选择或新建）。完成后拿到一个 `*.pages.dev` 网址。

> 此时网页能打开，但**还登不进去**：`PASSCODE` 环境变量和 D1 绑定都没配，接口读不到口令、连不上数据库。这是正常的，下一步补齐即可。

**步骤 4：回控制台配好口令与数据库绑定**

进入 Cloudflare Dashboard → **Workers 和 Pages** → 选中刚创建的项目：

- **Settings → Variables and Secrets**（旧界面叫 Environment variables）添加三条：
  - 名称：`PASSCODE`，值：初始登录口令（只在口令表为空时用来生成第一条口令），环境：Production（建议 Preview 也加一份）
  - 名称：`ADMIN_PASSCODE`，值：新口令「管理员密码」的初始值 / 兜底回填值，环境：Production（建议 Preview 也加一份）
  - 名称：`SUPER_PASSCODE`，值：只有管理员知道的超级密码，只用于登录页的「管理口令」，环境：Production（建议 Preview 也加一份）
- **Settings → Functions → D1 database bindings** 添加绑定：
  - Variable name：`DB`（必须叫这个名字，代码就是按它取数据库的）
  - D1 database：`team_building`

（本地开发由 `wrangler.toml` 提供绑定；线上需要在这里再绑一次。`SUPER_PASSCODE` 若不配置，登录页的「管理口令」会返回 `500 服务器未配置超级密码…`；`ADMIN_PASSCODE` 只影响新口令「管理员密码」的初始值——项目级操作校验的是各口令自己的管理员密码。）

**步骤 5：再部署一次，让配置生效**

```bash
npx wrangler pages deploy public --project-name=team-building-site --branch=production
```

（在 Dashboard 点一次「重新部署」效果相同。）完成后打开 `*.pages.dev`，用第 4 步设的口令登录。

**步骤 6：验证**

- 能进登录页，输入口令后进入项目中心；
- 新建一个项目并添加两三个家庭，刷新页面数据还在——说明 D1 绑定正确、写入正常。
- 在登录页点「管理口令」，输入 `SUPER_PASSCODE` 能看到口令列表——说明超级密码已生效；
- 在日志页删一条日志或点「清除全部日志」、在项目中心结束一个测试项目、在项目中心删一个测试项目，都能弹出密码框、输入该口令的**管理员密码**后成功——说明「按口令的管理员密码」已生效。

### 二、后续更新

项目已存在时，改完代码直接推，不需要重复上面的配置：

```bash
npx wrangler pages deploy public --project-name=team-building-site --branch=production
```

`npm run deploy` 等价于上面这条命令（只是不带 `npx` 前缀）。如果工作区有未提交改动，wrangler 会打印一条 warning；`--commit-dirty=true` 只是用来消掉它并给部署打一个 dirty 标记，**不影响实际上传的文件**，也不代表「用 Git 发布」，所以本项目命令里不带它。

若这次更新包含**数据库结构变化**，部署后通常还要对线上库执行升级 SQL（`schema.sql` 用的是 `CREATE TABLE IF NOT EXISTS`，对**已经存在**的表不生效，所以新增字段必须手动 `ALTER`）。本版新增「多口令」与「按口令的管理员密码」，对应三条：

```bash
npx wrangler d1 execute team_building --remote --command "CREATE TABLE IF NOT EXISTS passcodes (id INTEGER PRIMARY KEY AUTOINCREMENT, passcode TEXT NOT NULL UNIQUE, name TEXT NOT NULL DEFAULT '', admin_passcode TEXT NOT NULL DEFAULT '', created_at TEXT NOT NULL DEFAULT (datetime('now')))"
npx wrangler d1 execute team_building --remote --command "ALTER TABLE projects ADD COLUMN passcode_id INTEGER"
npx wrangler d1 execute team_building --remote --command "ALTER TABLE passcodes ADD COLUMN admin_passcode TEXT NOT NULL DEFAULT ''"
```

> 也可以一条都不执行：后端首次请求会自己补建口令表与这两个字段，口令表为空时用环境变量 `PASSCODE` 生成「默认口令」，并把还没有归属的项目归到它名下、把还没有管理员密码的口令用 `ADMIN_PASSCODE` 初始化。上面的 SQL 只是想在库里显式留痕时执行。

本地开发库同理（把 `--remote` 换成 `--local`），或直接删掉 `.wrangler/state` 后重新 `npm run db:init` 建库。旧版本升级到当前版本的其余历史变更，`schema.sql` 顶部注释里也逐条列了对应的 `ALTER` 语句。

**本次「家庭人数 + 分摊方式」版升级**（老库必须补两列并把历史成员行数回填成人数）：

```bash
npx wrangler d1 execute team_building --remote --command "ALTER TABLE families ADD COLUMN member_count INTEGER NOT NULL DEFAULT 0"
npx wrangler d1 execute team_building --remote --command "ALTER TABLE projects ADD COLUMN split_mode TEXT NOT NULL DEFAULT 'family'"
npx wrangler d1 execute team_building --remote --command "UPDATE families SET member_count = (SELECT COUNT(*) FROM members m WHERE m.family_id = families.id)"
```

> 顺序不能反：先补 `member_count`，再回填一次。回填只应在升级时执行一次；重复执行会把用户后来手动改成 0 人的家庭又改回历史行数。
> 也可以一条都不手动执行：后端 `ensureSchema()` 首次请求会自动补两列，并且**只在 `member_count` 是本次真的新建出来的情况下**自动回填一次，然后把 `schemaEnsured` 置为已就绪。线上多实例部署时，若想确保回填结果确定可控，建议按上面三条手工执行。
> `schema.sql` 已包含新列定义，全新安装（或删掉本地 `.wrangler/state` 重建）不需要再执行 `ALTER`。

### 三、改用 Git 集成自动部署（可选）

也可以让 Cloudflare 在每次 push 时自动构建部署：

1. Dashboard → Workers 和 Pages → 创建 → 选 **Pages** → **导入现有 Git 存储库**，授权后选好仓库；
2. 构建配置：**Build command 留空**，**Build output directory 填 `public`**（纯静态项目，没有构建步骤）；
3. 点保存并部署，拿到 `*.pages.dev`；
4. 首次同样要回到 **Settings** 配好 `PASSCODE`、`ADMIN_PASSCODE`、`SUPER_PASSCODE` 三个环境变量和 `DB` 的 D1 绑定，然后再触发一次部署。

之后每次 push 会自动重新部署。

| PUT/DELETE | `/api/passcodes/:id` | 修改（口令 / 管理员密码 / 备注名，可只传要改的字段）与删除口令。**需超级密码**；**删除时若该口令名下还有项目会被拒绝** |
| GET | `/api/projects` | 项目列表（含家庭数 / 各家庭人数之和 / 已花费统计）；**只返回当前登录口令名下的项目** |
| POST | `/api/projects` | 新建项目（可同时写入各家庭的 `name` / `member_count` / `note`），归属记到当前登录口令。**需当前登录口令的管理员密码**（`X-Admin-Passcode`）：缺失返回 `403 该操作需要本口令的管理员密码`，错误返回 `403 管理员密码不正确`；人数非 0～999 整数返回 `400 家庭人数必须是 0～999 的整数`；**同一口令下项目名重复返回 `409 该口令下已存在同名项目「X」，请换一个名称`**（去首尾空格、忽略英文大小写；不同口令之间不冲突）；**同一次提交的多行家庭名重复返回 `409 家庭名称「X」重复了，请合并或修改其中一行`**（同一项目内家庭名唯一，在建项目之前校验） |
| GET/PUT/DELETE | `/api/projects/:id` | 项目详情 / 改名改状态改预算改分摊方式 / 删除（级联清理）。`PUT` 可带 `{ "name": … }`（改名）、`{ "status": … }`（结束 / 重启）、`{ "budget": 数值 }`（设置 / 修改预算，必须 ≥ 0，填 `0` 表示取消、显示「无」）、`{ "bonus": 数值 }`（任务奖金池）、`{ "split_mode": "family" \| "person" }`（切换分摊方式，其它值返回 `400`）。**改名、结束 / 重启项目、删除项目、设置 / 修改预算与奖金、切换分摊方式，都需当前登录口令的管理员密码**；只改备注不需要。**改名撞上同一口令下已有项目名同样返回 `409`**（保存原名、只改预算 / 状态等不触发判重）。项目详情与列表都返回 `budget` / `bonus` / `split_mode` |
| GET/POST/PUT/DELETE | `/api/families[/:id]` | 家庭（需项目上下文）。`POST` / `PUT` 接受 `name`、`member_count`（0～999 整数）、`note`（忌口 / 过敏，家庭级一条）。**写操作只能作用于自己所属家庭**，否则 `403`；**`POST` 新增 / `PUT` 改名撞上本项目已有家庭名（去空格 + 忽略大小写）返回 `409 本项目已存在同名家庭「X」，请换一个名称`**，只改人数 / 备注或原名保存不触发判重 |
| GET | `/api/members[/:id]` | **历史成员数据只读**：GET 仍可查旧版按姓名录入的行；`POST` / `PUT` / `DELETE` 一律返回 `403 成员已改为按「家庭人数」登记，请到成员页修改人数与备注`。人数以 `families.member_count` 为准 |
| GET/POST/PUT/DELETE | `/api/carry-items[/:id]` | 携带物品（需项目上下文）。`PUT` 可只带 `{ "quantity": … }` 修改数量（自由文本、去首尾空格，留空表示清空；名称不改），也可带 `{ "status": … }` 切换待带 / 已带；**改自己家庭的物品才允许，别家返回 `403 只能管理自己家庭的携带物品`**。**`POST` 添加时同一家庭内物品名重复（去空格 + 忽略英文大小写）返回 `409 你家已添加同名物品「X」，请直接修改它的数量或换个名称`**，别家同名不冲突，前端也会先用缓存列表预检。`PUT` 仍保留改名称的能力但前端不提供该入口，改名称不触发判重。操作日志会记下「数量 旧 → 新」或状态变化 |
| GET/POST/PUT/DELETE | `/api/shopping-items[/:id]` | 采购清单（需项目上下文）。`PUT` 带 `{ "claim": true }` 接单、`{ "claim": false }` 取消接单（**已经采购过的项取消接单会被 `403` 拦住，要回「未接单 + 待购」只能删掉对应的采购记录**）；**状态由采购记录派生，`PUT { "status": … }`（只要与当前值不同）一律返回 `403 采购状态由「采购记录」自动同步，不能手工修改`**；读接口返回的 `status` 是按采购记录现算的值；**`DELETE` 删除清单项时，只要还有采购记录指向该项（即派生成「已购」）就会返回 `403 这一项已经登记过采购记录，不能从采购清单里删除；请先删掉对应的采购记录，它回到「未接单 + 待购」后即可删除`**，只有没有任何采购记录的项才能删 |
| GET/POST/PUT/DELETE | `/api/purchases[/:id]` | 采购明细（需项目上下文）。`POST` 登记采购时会联动采购清单：按 `item_id` 或同名项把该项标为「已购」，并在该项无人接单时把接单家庭记为本次登记家庭（已被他家接单则保留）；`DELETE` 删除采购记录**只能删自家登记的**（非登记家庭返回 `403 只能删除自家登记的采购记录，其他家庭只能查看`），删完按「还有没有记录指向该项」重新派生清单状态——一笔都不剩就回到「待购 + 没人接任务」。**删除采购记录不需要 `X-Admin-Passcode`** |
| GET | `/api/overview` | 概览统计（需项目上下文）：总花费、**`budget`（项目预算，`0` 表示未设置）**、家庭数、`member_count`（各家庭人数之和）、携带与采购完成进度 |
| GET | `/api/settlement` | 结算与转账建议（需项目上下文）。按 `projects.split_mode` 返回 `split_mode` / `effective_mode` / `person_count` / `person_fallback` / `basis` / `share`（人均或每家）/ `detail[].member_count` / `transfers` |
| GET | `/api/logs?since=&limit=` | 按 `id > since` 增量拉取操作日志，**倒序取最新的 `limit` 条后反转成时间正序**返回（默认 200、上限 500）；日志总数超过上限时新日志仍可见，不会永远停在最早那批（需项目上下文） |
| DELETE | `/api/logs/:id` | 删除单条日志（需当前登录口令的管理员密码） |
| DELETE | `/api/logs` | **清除当前项目的全部日志**（不带 `:id`）：只清 `X-Project-Id` 指定的项目、不影响其它项目，返回 `{ "ok": true, "deleted": N }`；需当前登录口令的管理员密码 |

除 `login`、`health` 与 `passcodes` 外，其余接口都需要 `Authorization: Bearer <token>`（登录后令牌与口令绑定，服务端据此判定当前口令，并按 `projects.passcode_id` 做项目隔离）；`/api/projects` 之外的业务接口还需带 `X-Project-Id` 指定当前项目；写操作建议同时带 `X-Family-Id`。

同一个请求头 `X-Admin-Passcode` 按路由承担两种校验：**口令管理**（`/api/passcodes`，登录页也能用，不要求登录令牌）比对 `SUPER_PASSCODE`；**项目级高风险操作**（新建项目 / 项目改名 / 删单条日志 / 清除全部日志 / 结束项目 / 删项目 / 重启项目 / 设置或修改项目预算）比对**当前登录口令的** `admin_passcode`。

项目状态为「已结束」时，**所有非 GET 请求都会被拒绝**（`403 项目已结束，只能查看；如需修改请先用本口令的管理员密码重启项目`），只有读取放行。
